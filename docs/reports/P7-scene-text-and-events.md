P7 implements offline German/English screen text recognition and timestamp-based scene events in `pilot.scene`. `TextReader.read()` accepts a 1280x720 RGB uint8 frame and returns recognized lines, full-frame pixel boxes, confidence, help, objective, subtitle, banner, phone/menu context and elapsed milliseconds. Apple Vision and Quartz are optional macOS dependencies, imported only when constructing the reader. No frame or recognized text is uploaded. There is no daemon, controller, network client or head call in this implementation.

`EventDetector.update(reading, timestamp, text=...)` returns immutable events containing kind, emission time, previous/current value, evidence description and the current SceneText. It can alternatively receive a frame and reader. It does not modify the minimap reader or contract. Timestamps must be finite and strictly increasing. First stable observations establish a baseline without a head call. A HUD change is a cutscene/menu hypothesis, and a flat/tilted map change is a vehicle-occupancy hypothesis; neither claims semantic certainty.

The detector requires at least three observations and one second for visible-HUD, vehicle and route transitions, two seconds for HUD absence, and 1.5 seconds for help/objective/banner changes. Gaps over two seconds reset pending transitions. Corrupt or low-confidence map readings reset pending map transitions. The minimap reader deliberately gives absent HUD readings confidence zero, so non-corrupt `minimap=none` must remain admissible. Hidden HUD does not imply vehicle exit or route loss. Missing OCR is unknown rather than empty. Normalized punctuation/case and a text similarity threshold of 0.86 suppress small recognition variations. Subtitle changes never emit events. Banner disappearance updates internal state without waking the head. These settings survived the measured 18–70 second comparison and the synthetic interruption tests; they are not a universal calibration.

Screen labeling is deliberately conservative. Large centered text matching German/English outcome labels is a banner before generic region assignment, including the actual German `bestanden` result. Help excludes numeric counters and text starting far from the left help panel. Objectives require an instruction prefix and colored target pixels; yellow, cyan, red and green targets occur or are supported. Uncertain bottom text remains available as subtitle context. This bounded vocabulary can miss unfamiliar instructions, and phone/menu regions can also contain world text. Consumers should not treat these fields as authoritative game state.

For head integration, pass each event's kind, timestamp, previous/current values, evidence and SceneText together with the caller's current Reading. HUD events carry the visibility hypothesis plus all available text. Vehicle events carry the map-projection hypothesis plus current instructions. Route events carry the old/new route color plus current objective. Banner events carry the recognized outcome text. Help/objective events carry both old and new instructions, while subtitle and phone/menu content stay supporting context. Events returned in the same tuple should be one head input; the caller owns queuing while a roughly seven-second head call is outstanding. There is no head/network integration in P7.
