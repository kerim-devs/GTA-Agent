`ControllerRuntime` in `loop.py` is the common safety core for `drive` and `play`. It accepts only distinct frames younger than 300 ms, releases once after a frozen stream, blocks output after HTTP 409 until a neutral retry succeeds, and never posts in shadow mode. Every nonempty pad state carries a 250 ms lease. Shared cleanup releases before stopping an owned recorder and continues cleanup after individual failures. The existing driving tests still pass.

`Conductor` reads the existing minimap pipeline on fresh frames and polls scene OCR in a separate daemon worker, at most twice a second by default. A stuck recognizer aborts through neutral cleanup after three seconds. Only one head request can be in flight. New scene events increment an epoch and accumulate while it runs; an older answer is logged as overtaken and cannot replace a plan or add a lesson. A startup request bootstraps the session, subsequent requests follow scene events, completion or failure of the whole queued plan, or 60 seconds without another request. Intermediate successful skills advance locally through the accepted plan; asking again after every intermediate step would defeat the requested sequence and add unnecessary head calls. Shutdown does not wait for a background job.

`Pad` represents all buttons, both sticks and both triggers. Every skill returns a complete state and a running, done or failed status. Plans are fully validated and constructed before replacing a running plan, with a neutral tick at replacement and neutral output at each skill boundary. `drive_route` uses its own existing `Driver` and ends neutral on route loss or failed recovery. Its duration is capped at 120 seconds; wait is capped at 60, walk at 10 and look at 5. Presses and shots accept 1 to 5 repetitions, 0.05 to 1 second per activation and a ten-second overall limit. Shooting aims with L2 for 0.2 seconds, fires with L2 and R2, then releases for 0.1 seconds before repeating. Walking clamps both axes and optionally taps cross at 4 Hz for the assumed standard PlayStation sprint layout. Looking clamps its requested angle to plus or minus 180 degrees and uses an uncalibrated 90-degree-per-second estimate, bounded by the requested duration. Neither the sprint mapping nor the camera estimate has been verified in the game.

`pilot play` adds `--shadow`, `--seconds`, `--head scripted|codex`, `--notebook`, `--set NAME=VALUE`, `--head-model`, `--head-effort`, `--head-timeout`, `--quiet-seconds`, `--no-record` and `--no-ocr`. The driver overrides also reach each new driving skill. The default play recordings and notebook live under `~/recordings/pilot`, outside the repository; a custom record directory supplies the default notebook beside its recordings. `--no-record` still creates a session directory for decision and pad logs. `--no-ocr` disables full-frame scene recognition. The offline tool disables both scene and GPS OCR unless explicitly enabled.

`head_prompt.txt` is loaded for every request. It explains GTA V, all available skills and their bounds, the cost of frequent requests, route following, cutscene waiting, uncertain situations, the German commentator sentence and the optional lesson. Each request contains events, help, objective, subtitle, banner, the complete minimap reading including GPS distance and turn arrow, the last or active skill status, notebook text and an absolute JPEG path. Each accepted response contains one to five calls, a nonempty sentence and an optional lesson. Unknown skills, unknown arguments or buttons, invalid counts, nonfinite values, invalid JSON and missing or oversized output are rejected as a whole. The prompt asks for a single German sentence; parsing bounds its text length but does not attempt linguistic verification.

The Codex adapter uses an argument list without a shell: `codex exec --ephemeral --sandbox read-only --skip-git-repo-check -c model_reasoning_effort=\"low\" --output-schema SCHEMA -o RESPONSE -i FRAME`, optional `--model MODEL`, and a final `-` to read the exact prompt from stdin. It runs from a temporary directory, defaults to low effort and a 45-second subprocess timeout, and reads only the output file. Local `codex exec --help` confirmed the flags with codex-cli 0.155.1. Tests use executable Python stand-ins for success, exit failure, missing output, malformed output and timeout. No real Codex request was made.

`head.jsonl` is the decision-log contract. A request row has `type=request`, a session-local integer `id`, `t` in the observation clock, the complete `request` object, relative `frame_file` and `prompt_file`, and initial `plan=[]`, `sentence=null`, `lesson=null`, `duration=0`, `applied=false`, `overtaken=false`. Its response row repeats that request and artifact identity, changes `type` to `response`, records completion `t` and wall-clock `duration` in seconds, and includes the validated plan, sentence and lesson when available. Only `applied=true` means the runner accepted the plan; it does not prove completion in the game. `overtaken=true` means a newer event invalidated it. Failures add `error`; shutdown produces an unapplied response for an outstanding request. OCR failures are separate `type=ocr_error` rows. Consumers should join request and response by `id`, filter by `type`, and use only applied decisions for commentary. Accepted lessons are appended with a UTC timestamp. `play.jsonl` records each tick's relative time, frame identity, freshness, reading, skill, complete result, send flag and HTTP status; offline rows always have `sent=false`.

## Review

Checked on 10 November. The default gate passes with 365 tests in 21 s. Eight breaks were tried: posting in shadow mode, applying an overtaken answer, ignoring a 409, a skill without a time limit, unknown skill arguments, several head calls at once and no release on the way out each fail a test. Dropping the neutral tick between two plans failed none; a test now pins that a replaced press is let go before the same button is pressed again.

The head may no longer press `ps` or `create`. Both leave the game for the console's own menus, which on a stream shows whatever the console shows.

The real head works through this code. The offline run was repeated and five of its saved requests were sent to the Codex CLI as the adapter builds the call: every answer was valid and arrived in 6.4 to 9.3 s, four of them in parallel. On the black first frame it waits for the cutscene, on foot in the garage it walks past the companion towards the exit, when the yellow route appears it drives it and names the car wash from the picture, on the "bestanden" banner it waits, and in a car without a route it waits three seconds. The recognition was off in that run, so the texts were empty and the head read the picture alone.

Still unproven and to be checked on the first live session: fetching the full frame on every tick instead of the HUD crop, which is 2.8 MB thirty times a second through the bridge; the recognition running next to the loop; how often the head is asked once text events are on; the sprint mapping and the camera turn rate.
