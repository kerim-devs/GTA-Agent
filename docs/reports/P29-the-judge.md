P29 adds an optional asynchronous visual judge to the pilot. The measured system prompt, joint questions, image encoding and letter/probability helpers moved from lab/judge/questions.py to pilot.judge; measure.py and sequence.py import them there. The runtime converts RGB to BGR before the unchanged 640-pixel, JPEG-quality-90 encoder. Its transport has a one-second timeout; laboratory calls retain their existing 120-second timeout. Requests disable proxies and redirects, and construction accepts only localhost, numeric loopback, RFC1918 or IPv6 unique-local addresses. No network or console connection was made for this work.

The reader starts at most once per quarter second, encodes and sends in background threads, discards timed-out or late results, and tries the next available server while cooling failed servers for two seconds. A still-blocked transport occupies only its own endpoint, preventing unbounded threads for that endpoint. Every result is delivered once. The conductor supplies the newest judgment and its capture age to the head, uses the contract's player_mode function for both carry conditions, and emits mode_changed only when the accepted state changes, including expiry. Mode events survive screen-reflex handling. Skills and the scene detector remain unchanged as required, so their existing minimap-based decisions are not fixed by this card.

The acceptance threshold is 0.98, above the legacy parser's 0.975 vehicle probability at the beginning of the exit sequence. Thresholds 0.95 and 0.97 accept that single vehicle answer; 0.98 waits for the two subsequent foot answers. Higher thresholds up to 1 do not improve these sequences. Two matching judgments accept a mode even without probabilities, and a fresh high-probability answer can accept immediately. Repeated or older capture timestamps do not count as a second vote. An accepted mode expires when the newest valid judgment's frame is more than one second old. Malformed, missing or disallowed letters reject the entire reply and log a failed request; partial replies are deliberately not aligned or used as votes.

The measured legacy letters helper strips token whitespace and overwrites duplicate decoded letter keys in top_logprobs. Consequently its normalized confidence can favor a letter other than the answer. For example, the first wanted-sequence foot answer has probability about 0.003, whereas its isolated vehicle flicker has probability rounded to zero. That behavior is retained to satisfy the exact-parser requirement, and the threshold is tied to this behavior. A parser correction requires remeasuring and choosing a new threshold; these probabilities must not be treated as calibrated confidence. This work does not establish the PLAN's accuracy or live latency targets anew.

With `pilot play --judge URL=MODEL` repeated in preference order, the session writes judge.jsonl. Each success contains t, capture, answers, probabilities, duration, server and mode. Answers map each question to its value and selected-letter probability, for example `"mode": {"value": "foot", "probability": 0.99}`; probabilities additionally holds the normalized alternatives by letter for each question. Failure rows contain the same timing/server/mode fields, empty answer/probability objects and an error. Time and capture use the runtime clock; duration and the head's age are seconds. A null accepted mode means minimap fallback, distinct from the string "none". Without --judge, no reader or judge.jsonl is created.

## Review

Two things in the delivered version were changed. The probabilities were wrong, as the worker noticed and kept for the sake of the measured parser: the model's letter arrives as several tokens, "A" and " A", and the parser kept the last of them instead of adding them up, which put 0.003 on an answer given with certainty. They are added now. The letters themselves, and with them every measured agreement, are untouched. With the probabilities right, the recorded sequences show that no threshold separates a wrong single answer from a right one: the one wrong "vehicle" on foot with stars came with 0.9997 and the wrong "none" in the middle of a drive with 0.997. So the rule is two judgments in a row and nothing else, and the threshold is gone. The audit gives the same result as before: twelve changes of the raw answer become three of the accepted mode, and on the stretch with the tilted map the accepted mode is on foot from the second judgment to the last, while the minimap says vehicle on 110 of those 120 frames.

The head is told of a change between two modes the judge has named. The delivered version also reported the judge's first word and every lapse to nothing, and each such event ends the running plan's claim on the head, so a server that stutters would have made the pilot plan afresh again and again.

The default gate passes with 1165 tests in 61 s. Still open and done next by the reviewer: the measurement of `lab/judge/measure.py` through the moved code against the server, and the judge running against frames in real time.
