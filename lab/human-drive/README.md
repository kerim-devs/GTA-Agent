Run from `pilot/` with `env -u PS5_HOST .venv/bin/python tools/human_drive.py <recording>... --out ../lab/human-drive/out`. Add `--sections <P38 output directory>` to select sections whose kind is `drive`. Without sections the eligibility rule is a tilted minimap, a detected route and active recorded steering or pedal input. Native macOS Vision access is needed for the existing GPS recognizer. The command never connects to the console or runs the object detector.

The tool reads video sequentially and samples capture-clock bins at 30 Hz using `frames.jsonl`, not MP4 timestamps. Missing bins are not interpolated. Exposure across a gap greater than 0.1 seconds is capped at one sample; driver and GPS history survive short network gaps and reset after a two-second discontinuity. Controller changes are held until the next event. Only `src=agent` is used for the pilot reference recording. An absent hand or a neutral initialization row produces a skipped result with no metrics.

Each recording gets `readings-v3.jsonl` and `drive.json`. The reader cache is derived, local data; use `--refresh` after changes to source recordings or reader configuration. The v3 reader fixes history loss across ordinary Wi-Fi gaps. After separate batches finish, run `env -u PS5_HOST .venv/bin/python tools/human_drive.py --out ../lab/human-drive/out --summarize` to rebuild the combined `summary.md`, `summary.json`, `divergences.json` and five contact sheets. The twenty extrema are separated by at least three seconds within each recording and ranked by absolute steering disagreement on sustained clear moments. `env -u PS5_HOST pilot/.venv/bin/python lab/human-drive/review.py`, from the repository root, adds three-frame context strips at approximately minus one, zero and plus one second, again using the capture clock.

The fitted lag is a correlation with visual heading response, not a separately validated command-to-picture delay. It includes vehicle dynamics and changing route geometry. Human command comparisons using that fit are provisional. The pilot check uses the existing 0.14-second `MEASURED_DELAY_S` as an explicit reference and reports its independent response fit separately; it does not claim to have remeasured 0.14 seconds. No-response recordings still retain zero-lag footage coverage and route-free spans, with uncalibrated alignment marked in the result.

All shares are weighted by observed time. A clear moment holds the same steering sign at magnitude 0.3 or greater for at least 0.3 seconds. Both majority-per-moment agreement and agreement across clear seconds are reported. Speed is the existing causal regression of OCR route distance. Curvature is the largest three-point curvature ahead, with the driver's configured stride and trim. The lateral-acceleration value is an ahead-path proxy using the existing 0.7 metres-per-pixel assumption. It is not measured tyre grip or actual acceleration at the vehicle. Bends use curvature at least 0.01 inverse pixels and straights below 0.005. The driver limit is observed from its actual speed planner, without replacing that planner.

Pedals retain the recorded hardware values. Full R2 means at least 0.95, released R2 at most 0.05 and L2 more than 0.05. Pilot throttle has hardware shaping, so it is not compared numerically with raw driver throttle. Lift timing is relative to a change in the ahead-path curvature threshold, not verified physical entry into a bend. Input recordings and the production driver configuration remain untouched.
