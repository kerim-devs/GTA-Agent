This corpus contains 150 recorded screenshots and their observations from local pilot sessions. The JPEGs are 448 by 252 pixels and total 2,319,284 bytes. The source session and original frame name are retained in situations.json; jpeg_path is made portable and unused notebook text is omitted. The set includes foot and vehicle travel, eleven objective observations, 45 night frames, daylight and rain, and one explicit stuck screen. Nearby frames are correlated; this is a diagnostic corpus, not an independent generalization estimate.

Every frame was visually inspected with its request and available candidate descriptions. The right array can contain multiple reasonable choices or be empty. Eight map or pause screens have empty labels because their requests lack the stuck event normally handled by the reflex. Frame 36 exposes conflicting movement evidence: the screenshot shows foot travel, while the old minimap observation implies a vehicle. Labels describe safe, reasonable choices, not whether the full skill later succeeds. The local check finds 333 registry-valid plans and a reasonable first choice in 141 of 150 frames (94.0%).

From the repository root, run `pilot/.venv/bin/python lab/chooser/measure.py` for the offline corpus checks. Run `pilot/.venv/bin/python lab/chooser/measure.py --probe` for failure timing against ephemeral loopback fake servers only. The probe uses the 1.5 second caller budget; timeout-results.json records the measured caller times. It never reads configured model endpoints. Candidate snapshots must still match the code before any measurement can run.

When the gaming PC is available, run `pilot/.venv/bin/python lab/chooser/measure.py --server http://192.168.0.248:1234=qwen/qwen3-vl-8b --timeout 1.5 --output lab/chooser/model-results.json`. This command has not been run. It reports accepted-answer accuracy, accuracy over all situations, abstention rate, correct abstentions, and median/p95/maximum caller latency at thresholds 0.4 through 0.9. Incorrect or unnecessarily abstained frames are written to wrong-frames at the starting threshold 0.5. An empty right array is counted as correct only when the model abstains. The server always receives one small image and a fixed question, options, and at most two explicitly observed objective/help lines.

The runtime threshold remains 0.5 and has not been calibrated against the real model. The measurement script deliberately collects scored answers at threshold zero and applies all requested thresholds to that same run. It does not change the runtime threshold or exercise the console.
